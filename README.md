# Retest_Indicator

## SR Flip Scanner V1.0

Bybit USDT 무기한 선물의 거래량 동반 돌파와 리테스트를 탐지하는 정적 웹 앱입니다. API 키와 자동 주문 기능은 없습니다.

### 실행

Node.js 22 이상:

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

클라우드에서 기본 npm 캐시 디렉터리에 쓸 수 없다면 `npm ci --cache /workspace/.npm-cache`를 사용하세요. 기존 체크아웃에서 작업하며 별도 Git worktree가 필요하지 않습니다.

브라우저 테스트:

```sh
npx playwright install chromium
CHROMIUM_PATH=/path/to/chromium npx playwright test
```

이 환경에서는 `/usr/bin/chromium`으로 PC 1440px, 모바일 390px에서 모의 API를 사용한 검색·필터·취소·재검색·오류 표시를 검증합니다. 스크린샷은 `test-results/`에 생성됩니다. `CHROMIUM_PATH` 미지정 시 `/usr/bin/chromium`을 사용합니다.

### 검색 및 계산

- 15분/1시간, ALL/LONG/SHORT, 거래대금·탐색 봉·거래량 배수·리테스트 기간·피벗·접촉 횟수·간격·평균 거래량 기간·최근 신호 기간을 설정할 수 있습니다.
- 전체 linear 종목을 페이지네이션하여 Trading/LinearPerpetual/USDT 결제·호가 종목과 거래대금을 필터링합니다. 거래대금은 조회 당시 24시간 값입니다.
- 각 돌파 직전 과거 100봉에서 우측 확인까지 끝난 피벗만 사용합니다. 동일 높이의 평평한 고점/저점은 엄격 피벗에서 제외합니다. 피벗 군집의 전체 가격 폭은 해당 시점 Wilder ATR(14)의 0.3배 이내입니다. 대표 가격은 중앙값입니다.
- ATR은 각 판정봉까지의 데이터로 계산합니다. 평균 거래량에는 돌파봉을 제외합니다. 데이터 시간은 오름차순 정렬하며 브라우저 검색 시작 기준으로 닫힌 봉만 분석합니다. 기기 시계를 정확히 유지하세요.
- 돌파 이후 1~12봉에서 접촉 및 확인을 검사하며 무효 조건을 먼저 적용합니다. 12번째 봉도 허용하고 13번째부터 만료합니다. 같은 봉 접촉·확인은 허용하되 진입은 종가로만 계산합니다.
- 동일 방향/가격 구간은 진행 중일 때와 최초 돌파의 리테스트 기간 동안 중복 생성을 억제합니다. 종료·유예기간 이후의 새로운 돌파는 별개 패턴입니다.
- 최근 진입과 현재 진행 패턴을 구분합니다. 상태별 확정 시각은 **봉 마감 시각(KST)**이며 이력을 카드에서 확인할 수 있습니다. INVALID/EXPIRED도 엔진의 `patterns`와 이력에 보존되며 현재 유효 결과 카드에서는 제외합니다.
- 목표는 기존 2차 목표인 돌파 이전 확정 박스권 높이의 투영값 하나만 사용합니다(LONG: SR + 박스 높이, SHORT: SR - 박스 높이). 기존 1차 목표 계산·표시는 제거했습니다. 손절은 최초 접촉부터 진입 확인까지의 극값 및 SR 버퍼를 적용합니다.
- 박스권은 돌파 이전 확정된 반대편 SR 중 가장 가까운 가격과 돌파 SR 간 거리로 정의합니다. 반대편 확정 SR이 없으면 목표는 계산 불가입니다. 진입가보다 수익 방향이 아닌 목표도 계산 불가입니다. 최소 손익비 필터는 이 단일 목표의 손익비가 조건을 만족할 때만 표시합니다.
- OI는 돌파봉 시작 이하의 마지막 표본과 돌파봉 시작 초과~마감 이하 표본을 비교합니다. 표본 누락·조회 실패는 신호 판정에 영향을 주지 않습니다. 양쪽 수치와 변화율을 표시하며 증가만으로 신규 롱 유입을 단정하지 않습니다.
- 최대 3개 종목 작업을 병렬 처리하고 종목 내 요청은 순차 처리합니다. HTTP/API 오류와 타임아웃(12초)은 최대 3회 지수 백오프(0.5/1/2초)로 재시도합니다. OI는 화면에서 해제할 수 있습니다. 취소는 진행 중 fetch를 중단하며 백오프 대기는 최대 2초 후 중단됩니다. 일부 종목 실패는 별도 집계·표시합니다.

### GitHub Pages 배포

`.github/workflows/pages.yml`이 main push 또는 수동 실행 시 단위 테스트와 빌드 후 `dist/`를 배포합니다. GitHub 저장소 Settings → Pages → Source에서 **GitHub Actions**를 선택하세요. 상대 경로 빌드를 사용하므로 저장소 하위 경로도 지원합니다. 현재 작업에서 원격 push나 실제 Pages 배포는 실행하지 않았습니다.

### 실 API 접근 제한 및 대안

2026-11-11 클라우드에서 `api.bybit.com` 요청은 프록시 CONNECT HTTP 403으로 차단되었고 실제 브라우저 fetch도 실패했습니다. 따라서 이 환경에서 실시간 전체 시장 검색, 실 OI 응답, Bybit CORS 허용 여부는 검증하지 못했습니다. 모의 API 테스트 통과는 실서비스 접근 성공을 의미하지 않습니다.

우선 환경의 허용 도메인에 `api.bybit.com`을 추가한 뒤 새 요청으로 재검증하세요. 허용 후에도 Bybit 지역 제한이나 브라우저 CORS 정책으로 실패할 수 있습니다. 브라우저 개발자 도구 Network에서 응답을 확인하세요. 오류는 화면에 표시하며 임의 예제 신호로 대체하지 않습니다.

GitHub Pages는 서버 프록시를 실행할 수 없습니다. 직접 호출이 불가능하면 사용자가 관리하는 Cloudflare Worker 등의 별도 HTTPS 읽기 전용 중계 서버를 배포하고 다음과 같이 빌드할 수 있습니다:

```sh
VITE_BYBIT_API_BASE=https://your-owned-proxy.example npm run build
```

중계 서버는 `/v5/market/instruments-info`, `/tickers`, `/kline`, `/open-interest`의 GET만 Bybit로 전달하고, Pages 원본에 대한 CORS 응답·OPTIONS·요청 제한·캐싱을 설정해야 합니다. 임의 목적지 프록시는 허용하지 마세요. 실제 경로는 모두 `/v5/market/` 아래이며 앱의 쿼리와 Bybit JSON 구조를 그대로 유지해야 합니다. 공개 타사 CORS 프록시는 사용하지 않습니다. 이 중계 서버는 본 저장소에 포함되거나 배포되지 않았습니다. Bybit 이용 가능 지역 정책을 준수하세요.

### 결과 카드 내부 차트

각 결과 카드 하단에 차트가 자동으로 표시됩니다. 별도 차트 버튼 클릭이나 캔들 API 재조회가 필요하지 않습니다. 화면 밖 카드는 스크롤로 가까워지면 자동 렌더링되며, 필터 변경·재검색 시 이전 차트 리소스를 해제합니다.

- 검색에 사용한 **동일한 확정봉 스냅샷**으로 캔들을 표시합니다. 실시간 갱신 차트가 아니므로 최신 결과는 재검색하세요.
- 돌파(노랑), 최초 리테스트(파랑), LONG/SHORT 진입 확인(초록/분홍)을 해당 봉에 표시합니다. 리테스트와 진입 확인이 같은 봉이면 두 마커를 모두 표시합니다.
- SR·진입·손절·유효한 목표가를 수평선으로 표시합니다. 대기 중이거나 계산 불가한 가격은 선을 생성하지 않습니다.
- 차트 시간축은 **봉 시작 시각(KST)**, 카드의 신호 시각은 **봉 마감 시각(KST)**입니다. 예를 들어 15분봉의 10:00 캔들에서 확정한 신호는 카드에서 10:15로 표시됩니다.
- 드래그 이동 및 확대·축소를 지원합니다. 기존 외부 TradingView 차트 링크도 그대로 유지합니다.
- 차트는 TradingView Lightweight Charts™(Apache-2.0)를 사용하며 앱 번들에 포함됩니다. 차트 라이브러리용 외부 CDN 요청은 없습니다. 배포에 라이선스 사본(`public/third-party/`)과 출처 표시를 포함합니다.

### 탐색 시장 필터

시장 스캔에서 **코인만 / 주식만 / 전체**를 선택한 뒤 검색합니다. 기본값은 **코인만**입니다. 시장 선택 변경은 다음 검색에 적용됩니다.

[bybit-wave-scanner](https://yunsangyeong.github.io/bybit-wave-scanner/) 원본의 `src/market.ts`, `src/api.ts`를 확인해 같은 분류 기준을 적용했습니다. Bybit `/v5/market/instruments-info?category=linear&limit=1000`의 모든 페이지를 조회하고 공식 `symbolType`으로 캔들 조회 전에 필터링합니다.

- 코인만: `symbolType=""` 또는 `innovation`.
- 주식만: `symbolType="stock"`인 개별 주식 기반 무기한 선물.
- 전체: ETF·원자재·외환·알 수 없거나 누락된 분류까지 포함.

종목명으로 분류를 추측하지 않습니다. 기존 Trading / LinearPerpetual / USDT 호가·결제 조건과 24시간 최소 거래대금 조건, 캔들 페이지네이션·확정봉 분석·OI·취소·차트·결과 필터는 유지합니다. 진행 통계는 선택한 시장에서 실제 조회하는 종목만 집계합니다. 일반 현물 주식이나 별도 주식 거래소를 조회하는 기능은 아닙니다.

### 종목별 결과 중복 제거

검색 결과는 최근 진입 신호와 진행 중인 패턴 영역을 합쳐 **종목당 한 카드만** 표시합니다. 상태·최소 손익비 필터를 만족하는 패턴 중 진입 확정 → 리테스트 중 → 리테스트 대기 → 돌파 순으로 우선하며, 같은 우선순위에서는 최신 확정 시각의 패턴을 표시합니다. 결과 개수도 중복 제거한 종목 수입니다. 원본 탐지 패턴과 상태 이력은 유지하므로 필터 변경 시 해당 조건에 맞는 대표 패턴을 다시 선택합니다.
